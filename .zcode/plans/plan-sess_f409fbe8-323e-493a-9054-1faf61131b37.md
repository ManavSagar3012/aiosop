### Fixes (in execution order)

**1. BLK-1: Add pytest-timeout + configure --timeout**
- Add `pytest-timeout = "^2.3.1"` to `[tool.poetry.dev-dependencies]` in `pyproject.toml`
- Add `--timeout=120 --timeout-method=thread` to `addopts` in `[tool.pytest.ini_options]`
- This makes CI produce a reliable pass/fail instead of hanging forever

**2. BLK-2: Add coverage gate**
- Add `--cov-fail-under=25` to `addopts` (current ~22%, set a floor that's just above current to prevent regression, then raise over time)
- Add `--cov-report=html` for a browsable report

**3. MAJ-4: Govern the 2 raw oracle httpx clients**
- `injection_oracles.py:449` — replace raw `httpx.AsyncClient(verify=False, timeout=10)` with a governed client or accept a `client` param (the oracle already accepts one in most paths)
- `sqli_oracle.py:375` — same treatment

**4. MAJ-3: Remove 9 duplicate vuln_agent branches (dual detection paths)**
- For each of the 9 task types that have BOTH a standalone agent AND a vuln_agent branch (csrf, ssrf, jwt, websocket, saml, file_upload, pollution, takeover, smuggling):
  - Remove the `elif task_type == "X_scan"` branch from `vuln_agent._execute()`
  - The standalone agent already handles it (and is the better implementation — it was the one fixed for B4 honesty)
  - This removes ~800+ lines from the monolith and eliminates the dead-code/dual-path problem

**5. BLK-3: Consolidate reporting/ package**
- Move `core/bounty_report.py` + `core/poc_generator.py` imports into `reporting/__init__.py` so `from ai_osop.reporting import render_bounty_report, generate_poc` works
- Add a deprecation note to `reporting/exporters.py` pointing to the real engine
- This makes `reporting/` the canonical import path for report generation, not a 75-line vestigial stub

**6. MAJ-1: Mark/remove 4 stub MCP adapters**
- For cloud_mcp, reporting_mcp, session_memory_mcp, attack_graph_mcp: add a clear `STUB — NOT PRODUCTION` docstring + raise `NotImplementedError` on any tool call (fail-closed, not silent fake data)
- This prevents the stubs from being mistaken for real implementations

**7. MAJ-6: Add per-class success metrics test**
- Add a test that asserts each detector class has a corresponding benchmark/test that proves it can detect + validate + produce evidence
- Pin the contract: every VulnClass with a scanner must have at least one test asserting confirmed=True on a positive case

**8. Final verification: run the same 7-step live verification**
- Steps 1-7 from the previous report
- Plus: confirm vuln_agent is smaller, no dual paths exist, coverage gate passes, timeout prevents hangs
