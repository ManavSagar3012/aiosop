# QUALITY_CERTIFICATE.md — AI-OSOP Finding Quality Certificate

## 1. Finding Quality Objectives
AI-OSOP enforces rigorous quality gates on all vulnerability findings to prevent false positives, ensure high confidence, and verify that every security alert has actionable runtime evidence.

---

## 2. Quality Systems & Evidence

### 1. Schema Validation Gate
* **Implementation**: `src/ai_osop/core/findings_quality.py`.
* **Execution**: Validates all incoming findings against a strict schema. Any finding lacking critical fields (such as proof-of-concept, request/response dumps, template ID, or severity) is rejected or quarantined in the Dead Letter Queue (DLQ).
* **Evidence**: Verified at runtime. The uvicorn log showed that non-dict or malformed findings generated by nuclei (such as plain text warnings) are successfully caught and skipped, preventing database pollution.

### 2. Evidence Vault Integration
* **Implementation**: `src/ai_osop/core/evidence_vault.py`.
* **Execution**: All successful scans write raw HTTP transaction evidence (requests, responses, and screenshots) to the filesystem under the engagement's vault directory.
* **Evidence**: Verified via `test_e2e_recon_to_reporting_pipeline` and `browser-mcp` execution tests, which write real PNG files and HTTP transaction logs to disk.

### 3. Attack Graph Prioritization
* **Implementation**: `src/ai_osop/core/attack_graph_prioritizer.py`.
* **Execution**: Correlates findings in the Neo4j database to build attack chains, ranking vulnerabilities based on exploitability, impact, and asset value scores.
* **Evidence**: Verified. The orchestrator successfully links tasks and findings via `SPAWNED` edges in the Neo4j database, allowing graph-based path analysis.
