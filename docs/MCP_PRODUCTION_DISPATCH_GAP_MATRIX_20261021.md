## Production call chain, authority and recovery

1. **Registry and transport** — `api/main.py:register_optional_mcp_servers` records separate connected/initialized/status. `mcp/protocol.py:MCPConnection.connect` requires `/health` HTTP200 without redirect; `initialize` first clears any stale tool manifest, then requires HTTP200, `status=ready`, exact provider server ID, unique named tools and original explicit `side_effect_class`, `requires_approval` and `scope_check=true`. Pydantic compatibility defaults **do not** mean the remote tool declared safety. Critical init additionally requires an open connection and matching initialized state. Optional server connections often remain only **registered**. `api/routers/mcp_tool_catalog.py` shows non-executable descriptions with `execution_authorized=false` and `runtime_health_verified=false`.
2. **Original signed human Action** — `api/routers/flow_mcp_actions.py` checks actual human bearer/role/expiration, strict duplicate-free JSON, explicit confirmation and expected signed Flow/engagement/revision/version. `orchestrator/flow_mcp_action_executor.py` and `memory/flow_mcp_action_dispatch.py` require actual original signed ROE, owner/Task/Subtask, separate approved operator and live lease, reviewed bounded primitive parameter/manifest hashes and scope/budget. Generic consequential scanner names and opaque bodies/headers are denied. Explicitly reviewed Browser navigate is the only RECON_ACTIVE exception; the SourceMap exact original SHA tool is narrowly allowed READ_ONLY. `prepare → reserve → mark_dispatched` commits original 0027 `dispatch_attempted` **UNKNOWN before provider I/O**.
3. **Tool transport / native** — `MCPConnection.execute` deep-copies the original request, rejects duplicate request IDs, runs `check_tool_authorization`, quota and durable event callback, then rechecks mutable bindings/current authority immediately before HTTP send; all provider requests have finite timeouts and disallow redirects. `X-OSOP-Native-Grant` can be passed **only** for inert `authority_status`: original 0029 source issues an Ed25519 one-shot grant, shared Go SDK verifies server/request/manifest/expiry and redeems over separately pinned HTTPS. Go `Server.Handler` never calls dormant legacy `Tool.Handler` via MCP ingress. Browser uses independent central 0034, SourceMap uses independent central 0035.
4. **Result/evidence settlement** — `MCPConnection.execute` strips untrusted `metadata.signed_provider_receipt` and requires exact fresh Ed25519 under a separately configured provider key for verified terminal reconciliation; `mcp/receipt_attestation.py:provider_receipt_is_signed` checks request, server, tenant and Task. `FlowMCPActionStore.reconcile` will not change original UNKNOWN based on HTTP200, success JSON, LLM assertion, forged signed flag or unsigned status. `flow_mcp_actions.py:_public_record` exposes `target_effect_verified=false` and `safe_to_automatically_retry=false`. Even correct provider signature is **provider testimony**, not independent target-effect or senior release proof.
5. **Uncertainty and recovery** — failed HTTP, timeout, ACK loss, missing/revoked original authority, changed source SHA or malformed signature retain UNKNOWN and prevent automatic consequential replay. `MCPConnection.get_request_status` requires a bound signed provider terminal in production. Browser's read-only `/mcp/request/status` returns unsigned `unknown / verified=false` if no terminal; SourceMap STATUS rereads current central source. Local journal alone is not multi-replica recovery, and generic Go inert redemption says nothing about actual scanner stop.
