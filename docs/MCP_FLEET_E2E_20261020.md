## Source-to-transport gaps, ranked

1. **[BLOCKER] No local endpoints**: no TCP listeners on the 11 effective loopback MCP endpoints or :8200. No observable initialization, actual tool catalog, provider identity, signed Task execution, server-side effect, replay handling, cancellation, or independent receipt. First qualify deployment **without** running tools against real targets.
2. **[HIGH] Shared Go SDK is an untrusted direct HTTP execution boundary**: `mcp-servers/go/sdk/server.go:36–69` registers `/health`, `/mcp/initialize`, and an unauthenticated `/mcp/execute` route that immediately calls `tool.Handler(req.Parameters)`. There is **no middleware in that SDK enforcing signed tenant/Flow/ROE/approval**. `security-bridge`, `nuclei`, `payload`, `shodan`, `threat-intel` source launches `server.Run(":port")` (wildcard binding). Do not expose these services to untrusted networks; prefer authenticated proxy and loopback/network policy, then provider-specific independent source-side admission. Recon includes a separate loopback-bind guard (`cmd/recon-mcp/main.go:161–163`).
3. **[HIGH] Tool declaration trust/classification mismatch**: Go `sdk.Tool` lacks `side_effect_class` in its JSON struct, while `MCPToolDefinition` defaults missing `side_effect_class` to **READ_ONLY**, `requires_approval` to false, and `scope_check` to true (`protocol.py:216–225`). Thus an otherwise running `sqlmap`/`nuclei` server may **advertise apparently safe metadata** despite a consequential handler. Treat all remote declarations as untrusted and require explicit server-signed classifications and independent Task/Flow enforcement. (The newer Flow MCP action executor separately restricts to bounded READ_ONLY tools and signed admission; this does not secure a directly reachable Go SDK port.)
4. **[HIGH] Bootstrap/health are not full readiness**: `MCPConnection.connect` validates only a GET `/health` **200 status**, not that the response contains the expected server ID, that tooling actually executes, or that remote security controls hold. During this qualification, `MCPConnection.initialize` was hardened to reject non-200 status, foreign `server_id`, non-ready status and duplicate declared tool names; six optional connections can still remain `_initialized=False` until their adapter explicitly initializes them. `system.py:130–183` and `mcp_tool_catalog.py:88–152` correctly label introspection as **unverified**; don't promote those dashboards to “E2E healthy”.
5. **[HIGH] Mock-as-success contamination**: `cloud_mcp.py:51–86`, `turbo_intruder_mcp.py:48–82`, `payload-mcp/main.go` and the three extra Python facades fabricate/sample results. 6. **[HIGH] Source-map fetch boundary**: `source_map_mcp.py:61–75` uses TLS verification **disabled** and fetches an arbitrary declared URL; lacks source-side SSRF/private-IP/redirect policy verification in the inspected function.
