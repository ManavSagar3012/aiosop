## Runtime call path and authority boundary

`src/ai_osop/api/main.py:register_optional_mcp_servers` declares **eleven** MCP slots and labels Browser, SourceMap, Nuclei, Cloud and Turbo *critical*. `MCPRegistry.register_server` in `src/ai_osop/mcp/protocol.py` opens HTTP health transport; `initialize_server` negotiates a typed declaration. The API's critical readiness check requires `ready` plus an initialized registry connection; initialization does not prove source grant redemption or target work. Five optional Go services can be merely registered in the API without completing critical initialization. A Go health 200 is specifically `configured_unverified`, with scanner execution false.

The six actual Go `cmd/*/main.go` entrypoints all call `sdk.NewServer(service)`, register legacy `sdk.Tool{Handler: ...}` closures and call `server.Run(...)`. **All remotely received `/mcp/execute` calls are handled by `mcp-servers/go/sdk/server.go:Server.Handler`, which never invokes those handlers.** `snapshotTools` strips handler references and, when independent native grant trust is present, exposes only SDK-owned `authority_status` with empty parameters. Without that trust, `/health` returns 503 and initialization declares `unavailable`, even though legacy declarations may be visible. The listener binds loopback; metadata `ScopeCheck` and `RequiresApproval` are not source-side authorization.

For the **inert** built-in only, the Go SDK verifies a strict bounded signed Ed25519 grant with matching `server_id`, `request_id`, `tool_name`, parameter and manifest hashes, signed Flow/Task/Subtask/Action/lease identifiers, READ_ONLY and a short validity window (`sdk/native_grant.go`). It then calls the separately pinned HTTPS `/native-grants/redeem` service with its own server credential. The 0029 source owns current authorization, revocation and durable one-use; a forged or independently expired grant cannot redeem. A resource-bound grant further requires separately signed and consumed supervisor proof, followed by a 0030 reviewed-byte offer. The Go result can state only `grant_durably_redeemed`, `native_target_execution_enabled=false`, `target_contacted=false`, `provider_contacted=false`. A signature, manifest, green health response or provider assertion cannot upgrade these facts.

The original 0027 Flow Action/source approval and 0029 native grant ledger are not interchangeable. The actual `src/ai_osop/orchestrator/native_mcp_docker_supervisor.py:provision_inert_grant` 0033 host provisioning branch presently accepts **`recon-mcp` only**. It expects real, fresh supervisor-side isolated-container observation bound to an issued grant; the other five cannot inherit that host-level status merely because they share an SDK. An in-process TLS or synthetic validator test does not qualify application DB durability or production multi-replica recovery. Transport lost ACK remains UNKNOWN and must be reconciled, never converted into scanner success.
