### What the new test proves

`tests/qualification/test_mcp_fleet_runtime_adversarial_20261021.py` uses actual production registry/client/source modules. Tests include:

1. **Exact all-eleven mapping** from AST of current API startup list to six Go commands, four native Python endpoints and the external Burp client. Go SDK's HTTP execute gate and Recon-only 0033 supervisor branch are source-checked; this is static evidence, not successful native scanner execution.
2. **Eleven genuine localhost TCP protocol handshakes against disposable fakes.** The real registry correctly completes health registration, then rejects a malicious HTTP 200 `ready` declaration that omits explicit tool risk metadata, resets negotiated tools/capabilities, and never calls `/mcp/execute` or `/mcp/cancel`. `127.0.0.1` bind uses an OS-assigned temporary port with no existing application listener. A successful TCP connection certifies only *this fixture*.
3. **A separate genuine localhost Burp adapter negotiation** offers correctly typed `READ_ONLY` tooling but omits `burp_signed_observations_v1`. The actual Burp adapter rejects it despite a successful registry initialization. Zero fake execution/cancel requests are sent; there was no installed Burp extension involved.
4. **Real Ed25519 status-receipt validator** uses an ephemeral fixture signer and enrolled public key for each of eleven names, verifies a correctly bound fixture, then rejects cross-service replay, foreign Task, post-signature tampering and expiry. The ephemeral private key is never a trusted operator signer, and a fresh signed *provider* receipt does not establish owner-of-record target effects.
5. **Eleven adversarial remote cancellations** call the actual `MCPConnection.cancel_persisted_execution` with a fake source authorization callback and in-memory HTTP 200 fake that claims `confirmed_stopped`, `verified=true`, `stopped=true` and a forged signature. Every result remains `unknown` even when the fake advertised signed cancel capability and the test accepted its synthetic intent. A foreign-server cancellation intent is denied before sending any HTTP request. This checks the downstream client only; real source authorization/CAS and physical worker stop are untested.
6. **Actual native ASGI untrusted requests** for Browser, SourceMap, Cloud and Turbo. Browser refuses unsigned production init, forged original-binding navigation and signed-status request without bearer (no Playwright launch). SourceMap refuses original artifact and STATUS without current trust; Cloud/Turbo reject executable requests. No app lifespan, external service or provider is started.
7. **MCP JSON parser adversarial input** rejects duplicate success keys, duplicate nested authorization fields, `NaN`, `Infinity` and numeric infinity. The separate real provider-result sanitizer recursively drops forged affirmative `verified`, `production_certified`, `target_effect_verified`, signed-receipt metadata, while preserving an ordinary finding count. These are in-process parser checks; the malicious payload never reaches an external service.
8. **Optional one real Windows Go command process, no scan**, gated by `OSOP_NATIVE_SIX_GO_PROCESS_RUNTIME_20261020=1`. Uses an owned temporary offline-built `payload-mcp.exe` and the existing safe PID-only loopback helper to exercise unavailable health, initialization and legacy handler 503. Skipped unless an operator explicitly opts in. This probe does not create a native grant, TLS redemption or any 0029/0033 source fixture and is excluded from default live-evidence claims.

The test's synthetic remote cancellations explicitly patch source authorization to isolate downstream verification. This is intentionally different from proving a real signed cancellation intent, current reviewer, revocation status, multi-replica durable ledger or actual physical cancellation. The HTTP fake is not a service provider; a signed fixture is not a production cryptographic identity; native ASGI without startup is not a running Playwright/browser or deployed SourceMap provider.
