# Reverse Engineering Malware

## Procedures

### Step 1: Initial Triage & Static Analysis
- Identify the file type, architecture, and potential packers or obfuscators.
- Extract strings, imports, and exported functions to understand high-level capabilities.
- Analyze file headers and resources for interesting artifacts or indicators.

### Step 2: Disassembly & Decompilation
- Use Ghidra or IDA Pro to disassemble the binary into assembly instructions.
- Analyze the pseudo-C code generated by the decompiler to understand program logic.
- Identify core functions, such as C2 communication, cryptographic routines, and evasion logic.

### Step 3: Dynamic Analysis & Debugging
- Execute the malware in a controlled, isolated environment (e.g., sandbox).
- Use debuggers (e.g., x64dbg, GDB) to step through code and monitor runtime state.
- Analyze system calls, file modifications, and registry changes during execution.

### Step 4: Protocol & Payload Recovery
- Reverse engineer network communication protocols to understand C2 commands.
- Extract and decrypt embedded payloads or configurations from memory or files.
- Document the full attack lifecycle and identify actionable indicators of compromise (IOCs).
